# Barotrauma API reference

| API | Purpose and limitations | Evidence |
| --- | --- | --- |
| `Item.ItemList` and `Item.GetRootInventoryOwner()` | Enumerate loaded items and resolve their outer inventory owner. For onboard collection, check the root's submarine and reject inventories owned by other characters. Enumeration alone does not establish access. | Barotrauma 1.13.5.0 client and server compilation verified on 2026-11-22. Existing uses in [MaintenancePatrol.cs](CSharp/Shared/MaintenancePatrol.cs) and [ExpeditionReturn.cs](CSharp/Shared/ExpeditionReturn.cs). The installed build's exact upstream source revision could not be retrieved. |
| `Deconstructor.InputContainer.Inventory` and `Deconstructor.IsActive` | Identify the machine's input inventory and observe whether it started. An active machine can still have an ingredient in its input. | Barotrauma 1.13.5.0 client and server compilation verified on 2026-11-22. Existing uses in [CrewDeconstructionObjective.cs](CSharp/Shared/CrewDeconstructionObjective.cs) and [CrewDeconstructionQuickstart.lua](Tests/CrewDeconstructionQuickstart.lua). The installed build's exact upstream source revision could not be retrieved. |
| `AIObjectiveManager.CurrentOrders`, `SortObjectives()`, `GetCurrentObjective()` | Native sorting calculates the order and autonomous objective priorities separately. The higher priority wins without removing the other entry. Ordinary orders use 60–70 and the emergency priority constant is 90. | Installed Barotrauma 1.13.5.0, build `0a9af9a7f0efeef46d63a4fe80103b4446a21dee`, IL inspected 2026-11-22. Exact upstream source unavailable. |
| `AIObjectiveLoop<T>.UpdateTargets()` and `Objectives` | Rebuilds target set using `FindTargets()`, then creates native child objectives. For immediate retargeting, clear the old child list and objective map before updating. Native `Reset()` clears the ignore list. | Installed Barotrauma 1.13.5.0 IL and client/server compilation verified 2026-11-22. |
| `AIObjectiveRepairItems.GetTargetPriority(Item, Character, float)` and `RequiredSuccessFactor` | Scores damaged devices using condition and repair success. The native threshold is 0.4. This score supplements target validity checks. | Installed Barotrauma 1.13.5.0 IL and client/server compilation verified 2026-11-22. |
| `OrderPrefab.Prefabs["reportbrokendevices"]`, `CrewManager.AddOrder(Order, float?)`, `Repairable.IsBelowRepairIconThreshold` | Native broken-device reporting passes a hull and a repairable component. When the component is supplied, the order constructor stores the component item in `Order.TargetEntity`. Play the localized order message only when `AddOrder` accepts the report. Vanilla skips reporting for a bot already acting on an item-repair objective. | Installed Barotrauma 1.13.5.0, inspected `HumanAIController.ReportProblems` IL and verified client/server compilation on 2026-11-22. |
| `ItemPrefab.Tags`, `ItemPrefab.DeconstructItems`, `DeconstructItem.IsValidDeconstructor(Item)` | Read resource tags and compatible outputs from the loaded prefab. Vanilla uses `ore`, `plant`, `plantitem`, and `seed`; oxygenite and sulphurite shards lack those tags. The condition interval and additional input requirements still apply. | Tags and recipes checked against installed Barotrauma 1.13.5.0 XML; API checked by client/server compilation on 2026-11-22. Exact upstream source for the installed build is **unverified**. |
| `Inventory.HowManyCanBePut(ItemPrefab, int, float?, bool ignoreItemsInSlot)` | Check input slots without treating current contents as permanent incompatibility. Use `CanBePut(Item)` against the live inventory before actually loading an item. | Barotrauma 1.13.5.0 client/server compilation verified on 2026-11-22. Exact upstream source for the installed build is **unverified**. |
